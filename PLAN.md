# PLAN.md — аудит ветки и готовность к портированию

## 1. Сводка и матрица совместимости

**Объект аудита:** публичный репозиторий-киг `infernogood/godot-to-aurora`, ветка `main`.

Текущая рабочая ветка `infernogood-stunning-goggles` совпадает с удалённой `origin/main` и указывает на коммит `564ed35` (`docs: rename project references to godot-to-aurora`). Открытых или закрытых PR в репозитории нет; удалённых веток кроме `main` нет.

| Критерий | Статус | Факт |
|---|---|---|
| Godot-проект | Блокер аудитного запуска | В репозитории нет `project.godot`, сцен, скриптов и `export_presets.cfg` |
| Версия Godot | Требуется адаптация | Кит рассчитан на Aurora-форк Godot `4.7.2-auroraos1`; проектная версия неизвестна |
| Рендерер GLES3 | Не проверен | В пресете настроены `gl_compatibility` через внешний Aurora-шаблон и ETC2/ASTC |
| aarch64/x86_64 | Требует окружения | Нужны Aurora-редактор и два шаблона; ни один бинарник сейчас не установлен |
| Aurora SDK 5.2+ | Блокер сборки RPM | SDK/Docker-образ не обнаружены в проверке окружения |
| Ключи подписи | Не проверены | Путь к `package-signing/regular_*` в SDK неизвестен |
| Эмулятор/устройство | Не проверены | `sfdk`, эмулятор и `/dev/kvm` в аудитной проверке не доступны |
| Жизненный цикл | Требует исправления в модуле | Найдено автоматическое размораживание при `FOCUS_IN` |
| UI/safe area | Требует проверки на проекте | Модуль чистый и headless-safe, но нет реальной сцены для интеграции |
| Сохранения | Требует тестов | Реализация использует `user://`, но атомарность и тесты не запускались |

## 2. Движок и шаблоны

Аурора-кит требует:

- `Godot_v4.7.2-auroraos1_linux.x86_64`;
- `auroraos_release.x86_64`;
- `auroraos_release.arm64`;
- `auroraos_debug.arm64`.

Проверка `fetch_engine.sh --check --print-paths` показала, что все компоненты отсутствуют в `~/.local/share/godot-to-aurora/engine` и export templates. Установить можно через локальный архив или GitHub Release:

```bash
./scripts/fetch_engine.sh --from-dir /path/to/engine
# или
AURORA_KIT_REPO=infernogood/godot-to-aurora ./scripts/fetch_engine.sh
```

Для сборки RPM текущий хост имеет `docker`, `patchelf` и `magick`, но не обнаружил Aurora SDK, образ `aurora-build-tools-*`, `sfdk`, редактор Godot и шаблоны.

## 3. Код, UI и ввод

На стороне кита изменения в игровом проекте пока не требуются: это сам каталог инструментов, а не Godot-игра.

| Файл/область | Находка | Оценка |
|---|---|---|
| `modules/aurora_lifecycle.gd` | `_on_focus_in()` вызывает `_resume()` при любом возврате фокуса, поэтому сворачивание может автоматически разморозить дерево | Критический; правка/тесты |
| `modules/save_service.gd` | Сервис соответствует `user://`, версия сохраняется в JSON-конверте; передаточный каталог сохраняется только под `user://` | Средняя; нужны headless-тесты |
| `modules/safe_area_helper.gd` | Есть защита от нулевой, некорректной и мониторной safe area; touch-target минимум 48 dp | Средняя; нужны реальные размеры/юнит-тесты |
| `scripts/lib/common.sh` | `KIT_MODULES`, `launcher_name`, `PKG_COMMENT`, `PKG_GROUP`, `PKG_CATEGORIES` объявлены как неиспользуемые; есть потенциальная путаница массив/строка в merge exclude filter | Низкая-средняя; lint ревью |
| `scripts/build_x86_64_rpm.sh` | SCons аргументы переданы через некавыченный substitution; требуется проверить на сборке шаблона | Средняя |
| `scripts/deploy_emulator.sh` | Зависит от реального SDK, registered device и KVM; парсинг и установка должны быть прогнаны на окружении SDK | Средняя |
| `export_presets.cfg` | Внешнего проекта нет, поэтому пресет и параметры пакета невозможно вывести | Блокер проектной адаптации |

`project.godot` отсутствует, поэтому нельзя проверить Godot 3/4, C#/GDExtension, нативные зависимости, ориентацию, physics engine, шейдеры, SubViewport, InputMap или тяжёлые ассеты.

## 4. Сборка RPM

Сборка не запускалась по причине отсутствия Godot-проекта и Aurora SDK. План следующей валидной проверки:

```bash
./scripts/build_x86_64_rpm.sh --check --strict
./scripts/fetch_engine.sh --check
./scripts/build_x86_64_rpm.sh --pck-only --import
./scripts/build_x86_64_rpm.sh
./scripts/build_aarch64_rpm.sh
./scripts/deploy_emulator.sh --check
```

Критерии сборки:

- для x86_64 пакет в `build/rpmbuild/RPMS/x86_64/`;
- для aarch64 пакет в `build/rpmbuild/RPMS/aarch64/`;
- RPM содержит только разрешённую структуру `/usr/share/<pkg>/`;
- сохраняемые данные находятся только в `user://`;
- бинарник не связан с X11/XWayland.

## 6. Риски

1. Без Godot-проекта нельзя определить совместимость шейдеров, C#/.NET, GDExtension и Godot 3.x.
2. В модуле жизненного цикла обнаружено нарушение требуемого ручного возобновления после сворачивания.
3. Нет опубликованного релиза или локального stash движка; `fetch_engine.sh` не сможет получить бинарники без исхода.
4. SDK 5.2 может иметь неустановленный Docker-образ `aurora-build-tools-*`; сборка шаблона займёт примерно 30 минут или потребует локального подготовленного образа.
5. Подпись и установка на продакшн недоступны без ключей SDK и зарегистрированного эмулятора/устройства.
6. Реальная совместимость Wayland/GLES3, safe area и сенсорного ввода требует headless и экранного прогонов.
